## 七、模拟器暴露的关键实证洞察（Task 04 规则统一决策直接输入）

1. **Web P0 单源修复后的净产出依然显著高于 iOS**：以 `Normal` 无广告通关为例，`web_pre_p0` 通关中位 **`26.5` 局**，修复双重入账后 `web_post_p0` 放缓至 **`50.5` 局**（12.63 天），但基因仍然因 100% 必掉 + 高额悬赏 + 狂暴 2x 持续大幅溢出，而 `ios_post_p0` 无广告需 **`77` 局**（19.25 天），靠高广告占比降至 **`51.5` 局**（12.88 天）。
2. **iOS 实战中发现两个极隐蔽的规则放大差**：① **iOS `PreySimulation.swift` 缺少 `recycleAndRespawn` 与 `26%` 悬赏刷鱼偏置**，导致实际有效捕食速率显著低于 Web，且悬赏任务 3 杀从随机池完成率极低；② **iOS 无时间难度膨胀（`globalDifficultyMultiplier = 1.0`）且 `5` 杀黄金 0 CD 狂暴**，令 iOS 狂暴覆盖率（~5%~8%+）大幅高于 Web（~1%~2.5%）。
3. **物理拾取率并非拍脑袋的 `85% / 92%`**：真实磁吸与清屏物理下，Web 与 iOS 常规航速对大多数掉落均能实现 **~95%~100%** 高收集（仅在高速冲刺急转或高密度连杀时因 iOS `11.0s` 超时产生小幅漏失），但双端基础产率、词条缺失与悬赏差距才是造成 `3x~10x` 跨平台分裂的核心原因。
4. **统一候选方案（`unified_candidate`）实测收口效果**：在保留单源拾取 + 35% 基因含 3 次保底 + 1.5x 金币狂暴 + 缩放悬赏 + 王冠金币压至 15% 后，`Normal` 无广告中位收敛在 **`62` 局（15.5 天）**、含温和广告 **`38` 局（9.5 天）**，可作为 Task 04 双端规则统一方案的关键量化基准。
5. **跨代垂直父级解锁路径（`P2-04`）实测节省约 15 万金币**：Web 端 `getParentCandidatesForForm()` 支持同列上代祖先（`(row-1)*8+col`）在 G4~G6 可省去每只新鲨从 `Lv.1` 升到 `Lv.6/8/9` 的昂贵升级费（实际消耗约 `~127万~132万 C`），而 iOS 仅允许线性前驱（`index - 1`）导致实际消耗拉满至 `~142.5万 C`；Task 04 必须统一双端父级规则，以免同一解锁标价产生两套真实成本。
