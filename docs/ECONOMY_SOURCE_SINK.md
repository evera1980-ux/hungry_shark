> **关键发现 —— Web 与 iOS “同名不同命”的单次吞噬数学差距**：
> 以 `T28`（`baseCoin=41`, `baseGene=13`）、倍率 `1.0x` 为例：
> - **Web 实得**：击杀直接加 `41C + 13G`，外加弹出 `5` 个拾取物（`3` 个金币各 `32` = `96C`，`2` 个 DNA 各 `15` = `30G`），单鱼期望总计 **`137C + 43G`**。
> - **iOS 实得**：仅弹出总值 `41C` 的金币（拾取率按 `85%` 计约 `34.9C`），以及 `38%` 概率（含 4.5% 黄金必掉约 `40.8%`）弹出 `13G` 晶体（期望约 **`4.5G`**）。
> - 结论：**同吃一条 T28 猎物，Web 的金币产出是 iOS 的 `3.9x`，基因产出是 iOS 的 `9.5x`！** 再叠加上悬赏、词条倍率差异，Web 中后期单局基因产出是 iOS 的 **`11x ~ 12x`**。

## 4. 四大经济结构性问题定性结论

1. **Web 端基因全面失去稀缺性（Gene Hyperinflation）**：
   - Web 全通总共只需 `113,453` 基因（含一次性王冠可抵消 `11,520` 仅剩 `101,933` 基因），但玩家进 G5 吃几把 `T37+` 猎物，**1 局就能刷 `3.7万~4.3万` 基因**。换言之，Web 玩家从 G1 到 G6 **基因存量永远是需求的 `3~6 倍`**。这也是后续绝对不能直接往 Web 塞“每日任务+大量基因”的原因——**若不先修复 Web 双重入账与掉率，任何基因奖励都会变成毫无价值的垃圾数字**。
2. **iOS 端“王冠送金倒挂 + 补给固定值失效”的双重失真**：
   - iOS 前三代（G1~G3）必经路径累计需 `45,921` 金币，但前三代 24 只鲨鱼王冠全拿光就能凭空领走 **`71,341` 金币**——**一次性成就奖励彻底覆盖掉了前三代的常规打金需求**；再叠加每天最高 `10` 次的 `SUPPLY_DROP`（`+3,000C / +250G/天`），轻中度玩家在 G1~G2 很容易“不用怎么游就买光鲨鱼，只卡深度或基因”。
   - 相反进入 G5~G6，必经路径狂飙到 `1,269,884` 金币，而王冠总共只补 `158,378` 金币（占比缩水至 `12.5%`），`SUPPLY_DROP` 每次 `300C` 更是降成 **解锁一只 `#47` 所需金币的 `0.68%`（点 150 次广告才够买 1 只鲨鱼）**，广告点击意愿归零。
3. **一次性奖励 vs 重复产出边界模糊**：
   - 目前只有猎物吞噬与局内悬赏属于稳定重复产出；所有王冠 (`11,520G` / `285,159C`) 均为一次性不可重复。由于缺少每日任务/每周挑战等**中等周期重复产出**，玩家在刷完低阶鲨王冠后若不想死磕后期单调刷图，会面临收入断崖与正反馈丧失。
4. **双端同一套商业配置表将引发经济灾难**：
   - 由于 Web 与 iOS 的实际单局产出差 **`3x~12x`**，若在 `P2-1` Phase C/D 直接给双端配同一套任务奖励与商店/广告礼包数值，必然出现 **“Web 领了当废纸，iOS 领了直接跳过两代”** 的严重事故。因此 **在实施 P2-1 Phase B/C/D 之前，必须先拉齐双端基础掉落口径**。
