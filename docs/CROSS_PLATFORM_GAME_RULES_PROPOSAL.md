## 一、核心设计原则与统一基准目标

1. **同行为同结果（Single Rule Truth）**：Web 与 iOS 玩家在相同操作、相同鲨鱼、相同成长阶段与相同生态事件下，必须获得**完全一致的经济产出、XP、狂暴触发率、王冠门槛、升级收益与门禁规则**。差异仅允许存在于输入方式（键鼠/触控摇杆）、渲染壳与技术适配器。
2. **禁止未经决策的跨端隐性分歧**：消除当前双端在生态补刷、时间难度膨胀、词条倍率、父级解锁路径与主动技能效果上的隐性分裂，并将全量经济常量统一收口至 [`shared/game_data.json`](../shared/game_data.json) 跨端契约中，避免 TS / Swift 两套硬编码继续漂移。
3. **非强制广告导向（Fair Progression Without Forced Ads）**：
   - 在**纯零广告**下，`Normal` 玩家（每日 4 局、~6.5 分钟/局）从 `#0 → #47` 全周期收敛在 **`60 ~ 80` 局（`15 ~ 20` 天）**；
   - 在**适度观看广告**下（非重度刷广告），通过 `SUPPLY_DROP` 与限量 `DOUBLE_SETTLEMENT` 提供约 **`25% ~ 30%` 加速**，使 `Normal` 收敛在 **`45 ~ 58` 局（`11 ~ 14.5` 天）**，广告收益占比严控在全周期总资源的 `<= 35%`。
4. **经济闭环须通过真实模拟器验证**：下文全部推荐规则均已在 Task 03 二维无头物理引擎（[`scripts/economy-simulator/`](../scripts/economy-simulator/)）或确定性全阶演算脚本中跑通对比；对仍存在的结构性张力（如深海基因掉率 vs `geneValue` 斜率）均给出定量诊断与产品拍板选项。

#### 1.2 设计理由、模拟影响与风险

- **设计理由**：
  1. Task 03 实证揭示，Web P0 修后虽消除了双重入账，但因 `rules.ts:969` `Math.max(1, ...)` 导致 `100%` 必掉基因、叠加 `2.5x` 词条与 `588G` 悬赏，正常零广告依然只要 `50.5` 局通关且结尾溢出 **`+415,497G`**；而 iOS 缺少 `recycleAndRespawn` 与 `26%` 悬赏偏置，导致实战猎物密度明显偏低、悬赏形同虚设。
  2. 将拾取率拉平：Task 03 证明在正常磁吸物理下，14–15s 寿命拾取收集率实际为 **`99.5% ~ 100%`**，统一 `14s` 寿命几乎零损耗且防 Web 粒子堆砌。
- **经济模拟影响**：在 Task 04 候选模拟实测中（已关闭高阶词条、采用 `30% + pity 3`、`1.5x` 金币狂暴、缩放悬赏），`Normal` 无广告从 Web 现行 `50.5` 局平滑拉长至 **`66` 局（`16.5` 天）**，含适度广告收口在 **`46` 局（`11.5` 天）**。
- **风险与待决策**：即便将基因概率降至 `30% + pity 3`，由于深海鱼 `prey.geneValue ≈ 0.31 × prey.coinValue`，伴随 130 万金币主线自然捞取的基因仍达 **`~29.4万 G`**（结局溢出 `~15.6万 G`）。是否需要同步收窄 `T18+` 单鱼 `geneValue`（改为 `~0.12 × coinValue`），见下文产品决策 **`D6`**。

#### 2.2 设计理由、模拟影响与风险

- **设计理由**：Task 03 暴露出 iOS 因 `8%` 黄金率 + `5` 杀 + `0s` 冷却 + `8s` 时长，实战狂暴覆盖率高达 **`2.2% ~ 7.9%`**（Web 仅 `0% ~ 2.0%`）；同时 Web 后期 `30.5% BEHEMOTH` 加剧基因通膨。统一为 `6` 杀、`15s` CD、`6.0s` 基础时长与 `6% ~ 16% BEHEMOTH`（仅 `T8+/220m+`）后，双端狂暴时间覆盖率实测收敛在 **`1.5% ~ 5.2%`** 区间。
- **风险与缓解**：向 iOS 引入 `ABYSS_BEHEMOTH`（`+1T` & `1.35x` 反击伤）可能提高 iOS G2~G4 中期海域危险度，故强制施加 **`tier >= 8 && depth >= 220m`** 浅海豁免保护。

### 模块 4：成长体系与 `Bite Tier` 专项深审（Progression & Evolution Audit）

> 本模块响应 Task 01/04 最高优先级专项要求：**不与基础经济公式混改，独立逐项核查全部升级属性增量、`Lv.5` 自身价值、`Lv.6` 突变与 `-1T` 倒挂、各代 `reqParentUpgradeLevel` 及 G5/G6 成本崖后，提出联动方案。**

#### 4.1 现状全身核查实证数据（基于仓库 `rules.ts` / `sharkEvolutionConfig.ts` / `GameRules.swift` 程序全量扫描）

1. **当前单级升级属性增量（`Lv.1 → Lv.10`，双端公式完全相同）**：
   - 生命值：`upgradeHpMult = 1 + (upLv - 1) * 0.08`（严格每级线性 `+8% baseHp`，例 `#16 Great White` 从 `Lv.1 403 → Lv.5 531 → Lv.6 564`）。
   - 速度与功耗：移速线性 `+2.2%/级`、饥饿减免线性 `-1.5%/级`、冲刺消耗减免线性 `-1.8%/级`、磁吸 `+8px/级`、能量 `+5/级`、体型缩放 `+0.006/级`。
   - 产出倍率：**`+0%`**（升级等级完全不增加金币/基因单价倍率）。
2. **`Lv.5` 自身价值实测核查**：
   - 当前代码在 `Lv.4 → Lv.5` 向玩家收取第一笔高额基因突破费（`#0..#47` 从 `13G` 爬升至 `1,476G ~ 2,995G`），**但 `Lv.5` 在属性表上没有任何额外阶跃收益**（与 `Lv.3 → Lv.4` 完全相同的 `+8% HP` 与 `T +0`），玩家花了基因却感受不到任何突破。
3. **`Lv.6` 突跃与 `23` 阶 `-1T` 进化倒挂成因**：
   - `upgradeBiteBonus` 目前写死在 `Lv.3 (+1T) / Lv.6 (+2T) / Lv.10 (+3T)`。
   - 一旦 G4（#24）起 `reqParentUpgradeLevel` 上调到 **`6`（G5 为 `8`、G6 为 `9`）**，父鲨在达标解禁下一只鲨鱼时已经触发了 `Lv.6 (+2T)`，导致 **`#23 → #46` 连续 `23 / 47` 次进化瞬间新鲨 `Lv.1` 咬合阶位反跌 `-1T`**，叠加 `45 / 47` 次进化 HP 瞬间缩水（最严重 `#42 Lv.9 → #43 Lv.1` **HP `-45.6%`**）与 `37 / 47` 次移速下跌。
4. **G5 / G6 成本 cliff（强化费反超新鲨解锁费 `2.56x`）**：
   - 升级费用 `round(baseUpgradeCoinCost * 1.36^(lv-1))` 叠加 `reqParent = 8/9`：
   - G5 强制父强化 **`223,725C`**（是 G5 解锁费 `115,200C` 的 **`1.94x`**）；
   - G6 强制父强化 **`682,787C`**（是 G6 解锁费 `265,600C` 的 **`2.57x`**），其中 `#46 → #47` 强制父强化高达 **`113,574C`**（`#47` 本身才卖 `44,400C`）。

### 实测关键诊断结论

1. **核心局数与广告健康度一次达标**：
   - 将 `DOUBLE_SETTLEMENT` 每日满额次数收敛至 **`2` 次**并关闭高阶 `2.5x` 极端词条后，`Normal` 在无广告下恰好稳稳收敛至 **`66` 局（`16.5` 天）**，看广告稳定至 **`46` 局（`11.5` 天）**，广告贡献占总收入 **`~27%`**，既给付看意愿又绝不挟持核心养成。
   - 原本在 Web & iOS 上 **全员 0% 通关率**（卡死 G6 `Lv.18`）的 `Casual` 玩家，仅因统一 `0.80x / 0.50x XP` 系数即已提升至 `33.3% / 66.7%` 通关；若产品在 `D7-2` 批准将 G6 `reqMaxInRunLevel` 下收至 `Lv.15`，轻度玩家也将获得完整可通关体验。
2. **揭示了一个仅靠调“掉落概率”无法解决的基因结构问题（须由 `D6` 决策）**：
   - 实测即使将普通鱼掉基因降到 `30% + pity 3`，`Normal` 在完成 `127万 C` 金币累计的同时，依然获得了 `29.4万 G`（远超 `11.3万 G` 必经基因与 `17.4万 G` 全满基因）。
   - **定量根因**：游戏主线所需总金币是总基因的 **`~12.5 倍`**（`1,422,842C vs 113,453G`），但生态库 `T18~T48` 的单条猎物定价中，`prey.geneValue / prey.coinValue ≈ 0.30`（`1 : 3.3`）。这意味着即使有效掉落概率低至 `40%`，捕食产出的 `基因 / 金币` 比值依然高达 `0.12`，再加上必掉基因的黄金鱼/巨兽/破甲/悬赏/王冠，整条主线基因必然长期维持金币的 ~`23%`，即天生存在 **`~2 倍` 基因过剩**。
   - **Task 05 解法**：欲真正实现 `D6` 中期稀缺张力，必须配合将 `T18+` 的单鱼 `geneValue` 曲线压薄约 `45% ~ 55%`（使全周期伴生基因落在 `~13万 ~ 16万 G`，刚好覆盖 `11.3万 G` 必经 + 少量留白给全满级与 `P2-1` 血统技能）。

## 四、整体风险与向后兼容清单

1. **Web 端玩家数值手感落差风险**：Web 从此前 P0 前双重入账 → P0 后单源 → Task 04 关闭 100% 必掉基因及压低悬赏与词条，单局基因获得会继续显著收紧。上线说明与版本同步期需确保老存档已积累资源不删档，并借 `SUPPLY_DROP` 与 `DOUBLE_SETTLEMENT` 首次上线补足商业化与正面引导。
2. **老存档与历史解锁兼容性（Backward Compatibility）**：
   - **严禁倒扣或回滚**：若某老玩家已通过旧版 `1.36` 公式或 `Lv.3/6/10` 制度解锁更高阶鲨鱼，升级版本后保留其全部 `unlockedSharkIds`、`sharkUpgradeLevels`、`bankedCoins`、`bankedGenes` 与 `sharkMasteryTiers`。
   - **未解锁节点无缝按新表校验**：仅未解锁的下一目标鲨鱼读取新的 `reqParentUpgradeLevel` 与 `Bite Tier` 规则，绝不会造成老玩家“已解锁鲨鱼变回锁定”或卡死。
3. **测试与自动化契约联动风险**：
   - 修改 `Lv.3/6/10 → Lv.5/10`、`DOUBLE_SETTLEMENT` 上限、`getSharkUpgradeGeneCost` (`max(12, ...)`) 及 `getGlobalAtlasBonuses()` 后，须同步更新 [`rules.test.ts`](../src/game/rules.test.ts)、[`GameRulesTests.swift`](../ios-native/HungrySharkEvolutionTests/GameRulesTests.swift) 与 [`scripts/build-ios-native.ts`](../scripts/build-ios-native.ts) 数据校验脚本（详见 Task 05 计划）。
