# 无限横向海洋地图：程序化生成与开发实施规范
版本：1.0 | 项目：2D 横向鲨鱼游戏 | 面向：AI 编程模型与游戏工程师

## 0. AI 开发硬约束
1. 先检查仓库、引擎、坐标系、地图代码、碰撞、渲染、存档和测试，再计划修改。
2. 增量实现，不得无理由重写现有项目。规范中的“必须/不得”是硬要求。
3. 地图按需生成 Chunk，禁止预生成整个无限世界。
4. 生成逻辑必须确定性；相同 worldSeed、generatorVersion、坐标、配置输出相同。
5. 地图生成核心禁止未受控 Math.random()；各子系统 RNG 流相互隔离。
6. 海床渲染、碰撞、采样必须使用同一地形函数/数据。
7. Chunk、缓存、对象池、队列必须有上限。
8. 按阶段开发、逐阶段测试和报告，不得跳过验收或假报测试。
9. 不明确的玩法/数值不得自行编造；使用注明的占位接口或提问。
10. 发生工程冲突时先列出冲突、影响、建议，不得擅自做架构性替换。

## 1. 目标与范围
- X 轴无限水平延伸，Y 轴为有限深度。
- 玩家可在规定深度范围内上下游动。
- 地图由连续海床、宏观 Biome、生态对象、POI、深度视觉和环境层组成。
- Chunk 按需生成、加载、激活、卸载；支持 Seed 复现、调试和持久化玩家改变。
- 不涵盖鲨鱼操控/战斗/成长/商业化数值；资源美术通过 assetKey 接入。

## 2. 坐标和 Chunk
世界坐标约定：X 向右为正且无限；Y 向下为正；Y=0 海面；Y=maxDepth 海底边界。默认 maxDepth=20000。
Chunk 使用左闭右开范围 [startX,endX)、[startY,endY)，负坐标索引必须用 floor：
```ts
chunkX = Math.floor(worldX / chunkWidth);
chunkY = Math.floor(worldY / chunkHeight);
chunkId = `${chunkX}:${chunkY}`;
```
若引擎坐标轴不同，仅在适配层转换。Chunk 是数据单位，不要求必然对应单独渲染节点。

## 3. 集中配置（默认初始值）
```ts
export const WorldConfig = {
  worldSeed: 123456789,
  generatorVersion: 1,
  bounds: { minDepth: 0, maxDepth: 20000, infiniteHorizontal: true },
  chunk: { width: 3000, height: 1500, preloadAhead: 4, retainBehind: 2, maxActiveChunks: 10 },
  biome: { macroWidth: 30000, transitionWidth: 6000 },
  terrain: {
    sampleStepX: 100, baseFloorDepth: 14000,
    largeWaveAmplitude: 2500, mediumWaveAmplitude: 900, smallWaveAmplitude: 250,
    minFloorDepth: 800, maxFloorDepth: 19800
  },
  generation: { staticObjectsPerChunkTarget: 24, minObjectSpacing: 120, deterministic: true },
  rendering: { backgroundParallax: [0.08, 0.18, 0.35], terrainParallax: 1.0 },
  performance: { generationBudgetMsPerFrame: 2, maxCachedChunkRecords: 64, maxPooledObjectsPerType: 300 }
} as const;
```
所有参数集中配置，不得散落魔法数字。启动时校验范围、正数、深度边界等；非法配置要报明确错误。

## 4. Seed 与 RNG
RNG 的输入至少包含 worldSeed、generatorVersion、chunkX、chunkY、subsystemKey。子系统键示例：terrain、flora、fauna、poi、ambient。不同子系统使用独立 RNG，新增鱼类不能改变 POI 结果。禁止以系统时间直接作为 Seed（除非用户选随机世界且实际 Seed 被存档）；禁止渲染帧消耗地图 RNG。
API 建议：`createChunkRng(seed, version, cx, cy, subsystemKey)`。对象 ID 必须稳定，可由 Seed、版本、类别、坐标/序号构造。

## 5. Biome 宏观生态区
首版类型：`coral_reef`、`rocky_shelf`、`open_ocean`、`underwater_canyon`、`deep_abyss`。`shipwreck` 作为局部 POI/特征，不把整片宏区都定义为沉船。
- X 方向宏区宽度默认 30000。
- 类型由 Seed + 宏区索引确定，Chunk 不得独立抽签。
- 边界默认过渡宽 6000，使用平滑权重混合颜色、装饰密度、物种概率等，不可所有参数瞬时跳变。
API：`getBiomeAt(x,y): {primaryBiome, secondaryBiome?, blend:0..1, depthBand}`。查询稳定且跨 Chunk 连续。

## 6. 连续海床
地形是全局函数，不能每 Chunk 独立随机端点。推荐 seeded 1D 连续噪声叠加：
- 大尺度波长 20k–60k，振幅 2500；
- 中尺度波长 4k–15k，振幅 900；
- 小尺度波长 800–4k，振幅 250；
- 基准深度 14000，采样间隔 100。
`floorY(x)=base + largeNoise(x)*A1 + mediumNoise(x)*A2 + smallNoise(x)*A3`。
使用 clamp 到 800..19800，并限制相邻采样坡度。坡度约束必须全局连续，不得只修 Chunk 端点。相邻 Chunk 共用边界采样点。
API：`getFloorDepthAt(x)`、`getTerrainSamples(chunkX)`。地形渲染、碰撞和海床装饰均基于同一结果。

## 7. 深度带与生态
首版可配置深度带：
| 名称 | 深度 | 视觉/生态 |
|---|---:|---|
| Epipelagic | 0–2000 | 明亮、光束、鱼群 |
| Mesopelagic | 2000–6000 | 光线减弱、浮游生物 |
| Bathypelagic | 6000–10000 | 深蓝、较稀疏 |
| Abyssopelagic | 10000–16000 | 黑暗、发光生物 |
| Hadal-like | 16000–20000 | 极暗、稀有生物 |
这些为游戏设计参考，非海洋学精确分区。

对象类型至少包括珊瑚、岩石、海草、鱼群、水母、发光生物、沉船碎片、气泡、浮游颗粒、海雪、洞穴、宝藏、地标。每类配置 type、Biome 白名单、min/maxDepth、spawnWeight、minSpacing、assetKey、collisionType、renderLayer、lifecycle。
生态须按 Biome、深度、地形距离、密度、间距约束生成；采用簇群中心分布，允许大片空海域，Chunk 边界不能出现明显密度断层。

## 8. Chunk 对象与生成管线
对象数据：
```ts
type GeneratedObject = {
  id: string; type: string; worldX: number; worldY: number;
  rotation?: number; scale?: number; variant?: string;
  biomeId: string; chunkX: number; chunkY: number; seedKey: string;
  state?: Record<string, unknown>;
};
```
生成顺序必须是：
1) 算 Chunk bounds；2) 查询 Biome/深度带；3) 创建独立 RNG；
4) 产生稳定候选点；5) 过滤深度/Biome/海床距离/边界；
6) 按权重选类型与变体；7) 检查间距（含邻 Chunk）；
8) 生成 POI 并检查唯一归属；9) 生成稳定 ID；
10) 按稳定规则排序；11) 输出纯数据，再由管理器创建渲染实例。
对象仅归属一个 Chunk。POI owner 为中心点所在 Chunk。跨 Chunk 显示不得重复生成。

## 9. POI
首版类型：shipwreck、cave、treasure、rare_creature_nest、landmark。POI 配置稳定 ID、中心坐标、尺寸、Biome/深度限制、占地半径、assetKey、触发器。需满足间距、占地不重叠、宏区密度上限。POI 可跨 Chunk，但仅中心 Chunk 管理生成/存档。存档只保存已改变状态（例如宝箱已开），静态内容由 Seed 重建。

## 10. Chunk 生命周期、相机与调度
状态：`unloaded -> queued -> generating -> ready -> active -> releasing -> unloaded`，允许 ready 直接 releasing。异步完成时检查 Chunk 是否仍需要；过期任务丢弃或进入有限缓存。
- 依据相机可视矩形算 Chunk。
- 朝移动方向提前加载 4 Chunk，身后保留 2 Chunk。
- 垂直仅按可视深度范围+缓冲加载，不能加载整列海洋。
- 停留/方向未知时对称预加载。
- 每帧生成预算默认 2ms；队列按可见性、距离、前进方向排序。
- 队列有上限；优先保留视野内任务。
- Worker 可生成纯数据，禁止直接操作引擎渲染对象。
- 视野外且不在保留区的 Chunk 释放渲染实例。

## 11. 渲染和深度视觉
渲染层建议顺序：far background、mid background、near background、ambient particles、creatures、terrain、terrain detail、POI、foreground occluders、UI。按项目引擎映射。
视差背景系数默认 `[0.08,0.18,0.35]`，海床 1.0；视差只影响视觉，不影响物理。
统一 API `getDepthVisualProfile(depth)` 提供亮度、色调、光束衰减、颗粒密度、发光比例、可见距离。随深度连续变化，浅层光束明显，深层趋向蓝黑；不得各渲染组件分别计算造成不一致。

## 12. 缓存、池与存档
- Chunk 数据缓存默认上限 64，使用 LRU/距离淘汰。
- 每类型对象池默认上限 300。
- 队列必须有上限。
- 归还对象池时清理位置、速度、动画、碰撞、引用、事件订阅和计时器。
- 不允许对象池持有已卸载 Chunk 的强引用。
- 存档至少含 worldSeed、generatorVersion、玩家进度（由游戏存档系统负责）、POI/对象修改状态、兼容信息。
- 不保存所有可由 Seed 重建的静态对象。生成算法变更必须升级 generatorVersion 并定义兼容策略。

## 13. 模块职责
| 模块 | 职责 | 建议接口 |
|---|---|---|
| WorldConfig | 参数和校验 | validateWorldConfig |
| WorldSeedService | RNG、稳定 ID | createChunkRng/createStableId |
| BiomeGenerator | Biome 查询/混合 | getBiomeAt |
| TerrainGenerator | 连续海床 | getFloorDepthAt |
| EcologyGenerator | 生态数据生成 | generateEcology |
| POIGenerator | POI 候选/占地 | generatePOIs |
| ChunkGenerator | 编排数据生成 | generateChunk |
| ChunkManager | 状态/调度/释放 | update(camera,player) |
| WorldRenderer | 数据转渲染实例 | activateChunk/deactivateChunk |
| WorldPersistence | Seed/改动状态 | save/load |
| WorldDebug | 调试叠层 | drawChunkBounds |
生成逻辑尽量纯函数/纯数据，输入显式，不依赖帧时间、相机或渲染节点。

## 14. 分阶段实施及验收
### A：坐标/Chunk 基础
实现坐标换算、索引、bounds、ID、配置校验、Chunk 网格调试。测试负坐标和边界。

### B：Seed/海床
实现 RNG、连续噪声、全局地形、采样、坡度限制；渲染和碰撞同源。验收 Seed 重启一致、任意查询顺序一致、边界无缝、深度/坡度合法。

### C：Biome/深度 Profile
实现宏区索引、Biome 确定性选择、平滑混合、深度带及统一视觉 Profile。验收稳定且过渡连续。

### D：生态/POI
定义类型配置、候选生成过滤、密度、群落聚集、稳定 ID、POI owner 和占地。验收深度/Biome 合规、边缘无重复、密度合理。

### E：Chunk 管理
实现状态机、相机范围、前向预载/后方保留、垂直缓冲、队列优先级、预算、卸载和上限。验收移动无加载空洞、远端释放、往返无泄漏。

### F：渲染/资源
实现 Layer、视差、海床、生物、POI、深度渐变；资源缺失显示占位且不崩溃。验收层次正确、深度效果连续。

### G：性能/存档/验收
调试统计、长距离探索压力测试、存档 Seed/版本和 POI 改动状态。完成所有测试和交付报告。

每阶段执行节奏：检查现状 -> 写改动计划 -> 实现当前阶段 -> 实际运行测试 -> 对照规范报告 -> 停止等待下一阶段确认。

## 15. 必须的调试项
开发开关显示：Chunk 边界/ID/状态、可见与预载范围、地形采样、Biome 权重、对象点位/ID、POI 半径/owner、Seed/版本、活跃 Chunk 数、缓存/队列/池大小、生成耗时、玩家/相机坐标。发布版默认关闭。

## 16. 性能目标与降级
首版目标：地图生成/调度每帧预算 2ms；活跃 Chunk 默认不超过 10（实际视野需要更多时先调整配置并记录）；缓存/池/队列有界；持续探索 10 分钟内内存不线性增长；地图结果可复现。
超预算先降级：远景粒子 -> 远处装饰细节 -> 背景动画 -> 远处非关键生物频率 -> 远端任务优先级。不可优先削减当前视野地形、碰撞数据、玩家附近关键 POI 和管理稳定性。

## 17. 自动化测试（必须）
1. Chunk 正/负坐标和边界；2. 配置非法值；3. Seed 复现；
4. 子系统 RNG 隔离；5. 地形 Chunk 接缝一致；
6. 地形深度 clamp；7. 坡度限值；8. Biome 复现；
9. Biome blend 0..1 且连续；10. 生态过滤；
11. 对象 ID 稳定；12. POI 跨 Chunk 唯一；
13. 状态机合法转换；14. 离开范围实例释放；
15. 缓存/池/队列上限；16. 过期异步任务不激活；
17. 往返探索静态可复现且修改状态恢复；
18. 长时间运行无无界内存/对象增长。

## 18. Definition of Done
- [ ] 无限 X、有限 Y 坐标正确；无全世界预生成。
- [ ] Chunk 按需生成，Seed/版本可复现。
- [ ] 海床连续，渲染/碰撞一致。
- [ ] Biome 宏观分区及过渡；生态符合深度/地形规则。
- [ ] POI 稳定唯一、有占地规则。
- [ ] Chunk 状态机、预载、卸载、预算均实现。
- [ ] 缓存、池、队列有上限。
- [ ] 深度视觉、视差、调试工具实现。
- [ ] 自动化测试和压力测试通过。
- [ ] 存档能恢复玩家对 POI 的改动。
- [ ] 无阻塞级接缝、重复 POI、持续内存增长问题。
- [ ] 交付测试报告、偏差和已知问题。

## 21. 核心原则
1. 无限世界不等于无限内存：只生成附近 Chunk。
2. 地形和宏观生态由世界坐标决定，不按 Chunk 随机拼接。
3. Seed 决定静态世界，生成顺序不能改变结果。
4. 生成纯数据，管理器负责实例生命周期。
5. 所有缓存和任务均有上限。
6. 渲染与碰撞同源。
7. 分阶段实现、测试、验收，不跳步、不假报。
8. 参数集中管理，供后续调优。

本规范优先构建可复现、连续、可扩展、可调试、性能受控且可由 AI 分阶段可靠实现的地图系统，而不是单纯生成视觉上“丰富”的场景。
